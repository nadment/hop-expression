= CAST, TRY_CAST, ::

Converts a value of one data type into another data type.

== Syntax

----
CAST( value AS type [ FORMAT format ] )
TRY_CAST( value AS type [ FORMAT format ] )
----

The xref:cast.adoc["::",role=op] operator provides alternative syntax.

----
value::type
----

== Arguments

value:: The value to convert.
type:: The data type to convert the value to. Date, Timestamp and Interval accept the number of digits of the fractional seconds, from 0 to 9, for example `TIMESTAMP(3)`, see xref:expression.adoc#fractional_seconds[fractional seconds]. Supported data types:
* Binary
* Boolean
* Date
* Inet
* Integer
* Interval
* Number
* String
* Json
* Timestamp
* Array of one of these data types, written with the data type of the elements followed by square brackets, for example `INTEGER[]`, `STRING(10)[]` or `NUMBER(10,2)[][]` for an array of arrays

format:: The optional format used for the conversion:
* a xref:numberformat.adoc[number format] to convert a string to a number or an integer, or a number or an integer to a string,
* a xref:dateformat.adoc[date format] to convert a string to a date, or a date to a string.

The type can also be written as a string literal, for example `CAST('1' AS 'INTEGER')`.

== Returns

The data type of the returned value is the type specified in the `AS` clause.

== Usage

* If the conversion is not possible, or the value exceeds the precision of the type, `CAST` raises an error and `TRY_CAST` returns NULL. An invalid format, or a format with a conversion that does not use one, like `CAST('yes' AS BOOLEAN FORMAT 'zz')`, raises an error in both cases.
* Boolean:
** A number is FALSE if it is 0 and TRUE otherwise; FALSE is 0 and TRUE is 1.
** A string accepts `true`, `t`, `yes`, `y`, `on` and `1` for TRUE, and `false`, `f`, `no`, `n`, `off` and `0` for FALSE, not case-sensitive and with the leading and trailing spaces ignored; any other value raises an error.
** A boolean converts to the string `TRUE` or `FALSE`.
* Integer and number:
** A string without format ignores the leading and trailing spaces, accepts an optional sign and an exponent, and can use the underscore `_` as a digit separator, for example `'1_000'::INTEGER` returns 1000. With a format, it is a number format model as in xref:to_number.adoc["TO_NUMBER",role=fun].
** The value is rounded to the scale of the type, 0 for an integer, and halfway values are rounded away from zero, for example `CAST(-1.5 AS INTEGER)` returns -2 and `CAST(1.25 AS NUMBER(3,1))` returns 1.3, also for a string, for example `'1.239'::NUMBER(10,2)` returns 1.24.
** `NUMBER` without precision and scale has no fixed scale, for example `1.23456::NUMBER` returns 1.23456, and `NUMBER(p)` has a scale of 0, for example `1.56::NUMBER(10)` returns 2.
** With a precision, an error is raised if the integer part has more digits than the precision minus the scale, checked after rounding, for example `CAST(12345 AS INTEGER(3))`, `CAST(999.5 AS INTEGER(3))`, `CAST(12345 AS NUMBER(3))` or `CAST('12345.6' AS NUMBER(3,1))`.
* Date:
** A string with a format is converted like with xref:to_date.adoc["TO_DATE",role=fun], and a timestamp like with xref:to_timestamp.adoc["TO_TIMESTAMP",role=fun]: two-digit years `YY` are interpreted with the variable `EXPRESSION_TWO_DIGIT_YEAR_START`.
** An integer or a number is the number of seconds that have elapsed since the epoch (00:00:00 UTC on January 1, 1970), and a date converts back to it; the fractions of a number are nanoseconds. The date is without time zone, its date and time are the ones of the epoch in UTC, for example `CAST(0 AS DATE)` returns DATE '1970-01-01', see xref:epoch.adoc["EPOCH",role=fun]. Converted to an integer or a number with a scale, the fractions of seconds are rounded like a number, for example `CAST(DATE '1970-01-01' + INTERVAL 1.5 SECONDS AS INTEGER)` returns 2.
** With a precision, like `DATE(3)`, the fractional seconds are rounded to the precision, halfway values are rounded away from zero, also for a timestamp and an interval, for example `CAST(TIMESTAMP '2020-05-25 20:48:00.6' AS TIMESTAMP(0))` returns TIMESTAMP '2020-05-25 20:48:01'.
** A date converts to a string without format with `YYYY-MM-DD`, followed by the time `HH24:MI:SS` if it is not midnight and by the fractional seconds if they are not zero, with the digits of the precision of the date, 9 by default, for example `CAST(TIMESTAMP '2019-02-25 12:34:56' AS STRING)` returns '2019-02-25 12:34:56' and `CAST(CAST(TIMESTAMP '2019-02-25 12:34:56.123456789' AS TIMESTAMP(3)) AS STRING)` returns '2019-02-25 12:34:56.123'.
* Timestamp:
** A timestamp has a time zone. A string keeps its time zone, a string without time zone is in the time zone of the system, for example `CAST('2020-05-25 20:48:00 +05:00' AS TIMESTAMP)`.
** A date without time zone is in the time zone of the system.
** A timestamp converted to a date keeps its local date and time, the time zone is dropped, for example `CAST(TIMESTAMP '2020-05-25 20:48:00 +05:00' AS DATE)` returns a date at 20:48.
** An integer or a number is the number of seconds that have elapsed since the epoch, converted to its instant in the UTC time zone like with xref:to_timestamp.adoc["TO_TIMESTAMP",role=fun], for example `CAST(0 AS TIMESTAMP)` returns TIMESTAMP '1970-01-01 00:00:00 +00:00'.
** A timestamp is accepted where a date is expected, like in the date functions.
* String:
** With a maximum length, like `STRING(3)`, the result is truncated to this length without error, for example `CAST('abcdef' AS STRING(3))` returns 'abc'.
** An interval converts with the format `+Y-M D HH:MM:SS.FFFFFFFFF`, the fractional seconds have the digits of the precision of the interval, 9 by default and none for `INTERVAL(0)`.
* Binary:
** A string converts to its UTF-8 encoding. To decode a hexadecimal or Base64 string, use xref:to_binary.adoc["TO_BINARY",role=fun].
** With a maximum length, like `BINARY(2)`, the result is truncated to this number of bytes without error, for example `CAST('ABC' AS BINARY(2))` returns the bytes of 'AB'.
* Inet: an empty string raises an error.
* Array:
** Each element of the array is converted to the data type of the elements, with the optional format, for example `CAST([1,2] AS STRING[])` returns ['1','2']. A NULL element stays NULL.
** Only an array is converted to an array type, with the same number of dimensions: `CAST(1 AS INTEGER[])` and `CAST([1,2] AS INTEGER[][])` raise an error.
** An empty array has no element to give its type, it must be cast to an array type, for example `CAST([] AS INTEGER[])`.
** If an element can't be converted, `CAST` raises an error and `TRY_CAST` returns NULL.

== Examples

----
CAST('yes' AS BOOLEAN) returns TRUE
CAST('Off' AS BOOLEAN) returns FALSE
CAST(TRUE AS STRING) returns 'TRUE'
CAST(2.5 AS INTEGER) returns 3
CAST(-1.5 AS INTEGER) returns -2
'1_000'::INTEGER returns 1000
CAST('abcdef' AS STRING(3)) returns 'abc'
TRY_CAST('-1234.56' AS INTEGER FORMAT '9999.99') returns -1235
'-1234.56'::INTEGER returns -1235
CAST('1,234.56' AS NUMBER FORMAT '9,999.99') returns 1234.56
CAST('24/05/2020 00:00:00' AS DATE FORMAT 'DD/MM/YYYY HH24:MI:SS') returns DATE '2020-05-24'
CAST(TIMESTAMP '2020-05-25 20:48:00.123456' AS TIMESTAMP(3)) returns TIMESTAMP '2020-05-25 20:48:00.123'
TRY_CAST(MAKE_DATE(2020,5,24) AS STRING FORMAT 'yyyy-q') returns '2020-2'
CAST(INTERVAL 5 YEAR AS STRING) returns '+5-0 0 00:00:00.000000000'
CAST([1,2] AS STRING[]) returns ['1','2']
['2020-01-01','2021-06-15']::DATE[] returns [DATE '2020-01-01',DATE '2021-06-15']
CAST([[1,2],[3]] AS STRING[][]) returns [['1','2'],['3']]
CAST([] AS INTEGER[]) returns an empty array of integers
----
